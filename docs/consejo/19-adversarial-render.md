# 19 · Revisión adversarial de geometría y render

Alcance: `crates/redes-core/src/{geom.rs, parts.rs, terrain.rs, view.rs}` y el pase GPU
`crates/redes-app/src/gpu3d.rs`. No se modificó ningún archivo del repositorio: cada hallazgo se
reprodujo con un crate temporal (`out/adv-render/probe`, ya borrado), con la CLI compilada
(`target/release/redes.exe`) o con capturas headless (`--snap`). Las líneas citadas son las del
commit `807a984`.

un proyecto de referencia `redes proyecto demo` (43 objetos, TIN de 4.602 triángulos) más

## Revisado sin defecto (para que no se repita el trabajo)

- `parts.rs`: no se encontró ningún defecto con consecuencia. `(r - 0.12).max(0.15)` nunca supera
  `r` porque `pozo_partes` fuerza `r >= 0.3` y `camara` `r >= 0.5`; `barra`/`barra_tapada` blindan
  la base ortonormal con `max(1e-5)` y la elección de `aux`; `prisma` exige ≥ 3 puntos; no hay
  indexación `[i]`, `unwrap` ni divisiones sin guarda. `tubo`, `tronco`, `anillo`, `disco` no
  producen NaN con parámetros del catálogo.
- `terrain.rs`: TIN de un solo triángulo, puntos duplicados (delaunator los tolera), TIN vacío
  (`z_at` = `None`, `z_range` = `(0,0)`), consulta exactamente en el borde del bbox y `reindexar`
  con bbox vacía funcionan; `slope_at` usa `h = max(step, 0.5)` (sin división por cero);
  `thinned` con celda gigante cae al clon completo (no rompe, aunque no aligera).
- `geom.rs`: `dist_to_segment`/`closest_on_segment` protegidos con `len2 <= EPSILON`;
  `polygon_area` devuelve 0 con < 3 puntos; `SegmentGrid::new` fuerza `cell >= 0.5`.
- `view.rs`: `expand` con 0 o 1 puntos no divide por cero; `etiquetas` se recorta a las 24 más
  cercanas y la seleccionada se añade al final (25 máx.); `recortar_extremos` acota `t` a 0,45.
- `gpu3d.rs`: `depth_slice: None` y `multiview_mask: None` son válidos para un target 2D;
  el uniforme mide 80 B y coincide con el layout WGSL (mat4x4 + vec4); `bytemap` respeta la
  alineación de `f32`; el pipeline declara el mismo `Depth32Float` que la textura.
